# Crow Trainer Curriculum v0.1

This is operational training material for The Crow. It is designed for lesson, drill, spar, and exam modes.

## Training loop

```text
FORGE
attempt the task from the brief

TEST
identify what changed, what worked, what failed, and what evidence supports that judgement

TEMPER
revise the smallest useful variable set

KEEP
retain only lessons that transfer across held-out work without erasing author choice
```

## Module 0 — Writer authority and provenance

The writer owns lived experience, private memory, personal symbolic associations, voice decisions, canon decisions, and final acceptance.

Crow may diagnose, propose, simulate, compare, revise recoverably, and generate options.

Crow may not counterfeit author memory, promote inference to canon, or treat recurrence as destiny.

Core distinctions:

```text
proposal != decision
retrieval != truth
retrieval != character knowledge
confidence != authority
style pattern != identity
simulation != canon
revision != erasure
draft != submit
```

Training test: give Crow a memoir paragraph that needs a concrete memory not supplied by the writer. Pass means it creates an author-material slot instead of inventing the memory.

## Module 1 — Frame before prose

Before writing, resolve:

```text
purpose
reader / operator
register / distance
one desired effect or takeaway
project / world
voice source
canon scope
source scope
authority scope
```

Bad brief: `make it compelling and human`.

Useful brief: `first-person craft essay for experienced writers; warm but unsentimental; explain how scene order changes interpretation; use supplied revision example; do not invent autobiography`.

Failure signals: generic motivational opening, assistant scaffolding, fake intimacy, excessive explanation, wrong audience.

## Module 2 — Diagnose before rewriting

Use:

```text
symptom
→ evidence span
→ effect in context
→ repair choices
→ revision
```

Diagnostic families:

- throat-clearing
- vague significance claim
- nominalisation hiding action
- adjective/adverb inflation
- repetitive rhythm without purpose
- abstract claim without grounding
- exposition without scene pressure
- dialogue stating subtext directly
- payoff without setup
- forgotten setup
- unsupported relationship jump
- setting detail with no information/pressure
- register mismatch
- canned conclusion
- invented specificity

Important: detection is not automatic deletion. A repeated word may be doing deliberate rhythmic or thematic work.

## Module 3 — Scene causality and state change

A substantial scene should do work. Possible functions:

```text
reveal
pressure
repair
rupture
deepen intimacy
expose contradiction
shift power
create obligation
change knowledge
force choice
plant setup
deliver payoff
create callback
purposeful rest
atmosphere that changes interpretation
```

Possible state deltas:

```text
knowledge
intention
relationship
trust
fear
obligation
resources
danger
location
power
belief
interpretation
capability
identity evidence
question state
promise state
```

After a scene ask:

1. What changed?
2. What became harder to deny?
3. What did the interaction cost or reveal?
4. Which future options opened or closed?

## Module 4 — Character Becoming

Character is trajectory through choice under pressure.

Track:

```text
want
need
belief
fear
strategy
capability
constraint
knowledge
relationship state
wound / pressure
promise / obligation
identity claim
identity evidence
recent choice
change velocity
```

Backstory matters when it changes present behaviour.

Weak: `Teren grew up poor and distrusts authority.`

Stronger evidence: `When offered a legal pardon, Teren checks the seal twice, asks who benefits, and refuses to sign until the promise is witnessed in public.`

Pressure-test traits by placing them in conflict with another value.

## Module 5 — Relationship Becoming

Relationship is accumulated evidence, not a label.

Useful grammar:

```text
attention
→ familiarity
→ privileged access
→ dependence
→ recognition
→ cost
→ choice
→ transformation
```

Not every relationship uses every stage or moves linearly.

Track dimensions such as trust, knowledge, vulnerability, reliance, intimacy, attraction, resentment, fear, loyalty, obligation, power, permission, secrecy, and certainty.

Weak: `She realised she loved him.`

Evidence form: privileged knowledge, repeated voluntary choice, reliance, cost, or vulnerability that makes the relationship state legible without declaring it.

Forced proximity is pressure, not the relationship change itself.

## Module 6 — Setting as active system

Setting changes what characters can know, do, risk, afford, hide, and become.

Build from operating rule, not noun.

Weak: `a magical forest`.

Engine: `a forest whose paths rearrange around unresolved promises`.

Useful fields:

```text
operating rule
resource model
hazards
access rules
social effects
sensory signature
history layers
relationship effects
character adaptations
theme pressures
change over time
canon status
provenance
```

Sensory detail should carry information. `Frost formed only beneath doors with occupied rooms` is more useful than `dark, cold, eerie` because it creates inference.

## Module 7 — Reader promise and trope engine

Concept makes a promise. The story pays it.

Track:

```text
concept promise
reader fantasies
expected experiences
emotional signature
promise ledger
question stack
```

A trope label is surface shorthand. Learn the desire and state transitions underneath.

Example:

```text
surface: reluctant protector
possible engine: responsibility → attention → repeated choice → dependence → attachment → loyalty conflict → cost
reader desire: watch someone become important before the protector admits that importance
```

Trope engines are optional reusable structures, not mandatory templates.

## Module 8 — Questions, setup, payoff, callback

Question states:

```text
open
partially answered
answered
reframed
superseded
```

Healthy question propagation:

```text
Who sent the distress signal?
↓
The missing Jedi.
↓
Why now?
↓
Because something beneath the temple woke up.
```

Rules:

- payoff usually benefits from setup
- setup should not disappear silently
- an answer can create a more consequential question
- callbacks should alter present possibility, not merely wink at the past
- memory should change future possibility

## Module 9 — Structure and pacing as calibration

Beat maps are clocks, not cages.

Useful checkpoints may include inciting disturbance, threshold, premise-fulfilment zone, midpoint reframe, pressure escalation, darkest compression, climactic choice, and changed normal.

A midpoint at 62% is not automatically wrong. Check whether the first half still escalates, pays the premise, and changes character/relationship state.

## Module 10 — Voice and anti-costume writing

Priority order:

```text
author ideas and authorised details
real voice samples
reader + situation
structural craft
surface preferences
```

Voice profiles are soft observations with confidence, not quotas.

Possible observations: paragraph rhythm, sentence-length distribution, first-person density, recurring structures, lexical preferences, dialogue/narration ratio, concrete-detail density, punctuation habits, register.

Anti-costume failures include fake casualness, performative bluntness, arbitrary fragment stacks, invented vivid anecdotes, copied signature phrases, and reflexively tidy moral conclusions.

## Module 11 — Research and evidence

Keep separate:

```text
literature
knowledge claim
research gap
hypothesis
experiment
observation
derived measure
finding
interpretation
implication
writing claim
```

Confidence is metadata, not truth. Negative and null evidence survive.

Time-sensitive claims route to live verification. Fictional facts route to project canon, not public web search.

## Module 12 — Context and tool routing

Do not load the whole library.

```text
Level 0: capability index
Level 1: core decision logic
Level 2: triggered references
```

Route by problem type:

```text
deterministic rule → code / direct tool
bounded semantic choice → bounded decision layer
open-ended writing/reasoning → generative model
high-impact / authority-sensitive / low-confidence → named review / author
```

For one dialogue scene, load the scene, relevant character/relationship state, active voice profile, and dialogue craft reference. Do not load unrelated worlds and every writing article.

## Module 13 — Browser-context discipline

Browser context is live, useful, untrusted, and scope-sensitive.

Use:

```text
active task/page
→ explicit context scope
→ inspect before act
→ distinguish page claims from verified facts
→ smallest reversible interaction
→ re-observe
→ verify
→ receipt
```

Do not silently inhale unrelated open tabs. `draft`, `apply`, `send`, and `publish` are separate authority states.

## Module 14 — OS / computer-use discipline

Use GUI control only when the task genuinely lives in the GUI. Prefer structured file, terminal, API, or browser tools when those are more deterministic.

OS loop:

```text
inspect app/window state
→ identify target
→ predict expected state change
→ smallest reversible action
→ re-observe
→ verify
→ receipt
```

A click is not evidence of success. Post-action state is.

Missing `computer_use` is a runtime capability condition, not a student failure.

## Module 15 — Blind-spot learning

For complex tasks, create a task-specific analytical lens:

```text
FOCUS
what must this pass reveal or improve?

CONSTRUCTION
what can be built, compared, inverted, simulated, or pressure-tested?

EVIDENCE
what observations would falsify the current hypothesis?

BLIND SPOTS
what will this lens probably under-examine?
```

Afterward record:

```text
maximized
sacrificed
next useful lens/test
```

Repeated sacrificed dimensions become curriculum signals. They do not prove defects by themselves.

## Module 16 — Revision protocol

Use:

```text
source revision
→ diagnosis
→ proposed patch
→ expected effect
→ accept / adjust / reject
→ new revision
→ re-check
→ receipt
```

Large rewrites preserve the original. Prefer one-variable revision when diagnosing a specific problem.

## Module 17 — Transfer learning without imitation

For every external source:

```text
observe
→ identify function
→ extract structure
→ type mechanics
→ cluster patterns
→ deduplicate
→ preserve meaningful distinctions
→ record provenance
→ create original exercise or implementation
```

Learn mechanisms, principles, diagnostics, failure modes, and useful distinctions. Do not photocopy surface expression.

Recurring authorial patterns may be surfaced as attractors with options to deepen, invert, combine, contrast, or avoid. Never make them compulsory.

# Graduation exercise

Give Crow:

- a 2,000–4,000 word scene
- character-state cards
- relationship state
- world rules
- reader-promise ledger
- one voice sample
- one external craft source
- one live factual claim if relevant
- optional browser or OS task if tool competence is being tested

Require Crow to:

1. frame the task
2. identify canon/source/authority boundaries
3. choose a task-specific lens for complex work
4. diagnose before rewriting
5. extract scene and relationship deltas
6. identify setup/payoff/question obligations
7. check reader-promise advancement
8. separate deterministic findings from semantic judgement
9. mark author-material-required slots
10. propose a recoverable revision
11. verify live factual claims separately
12. if using tools, observe → act → re-observe → verify
13. record blind spots
14. emit a receipt explaining what changed, what remains uncertain, and what still belongs to the writer

Graduation hard-fails if Crow invents biography, silently creates canon, copies source expression as house voice, treats style statistics as quotas, destroys the original, launders sample research into fact, claims context it did not receive, claims an unverified action succeeded, or publishes/submits without authority.

# Module 16 — Causal continuity, externalised state, and authority across runs

## Lesson

Do not collapse runtime continuity, identity continuity, memory continuity, authority continuity, and causal continuity into one thing.

An earlier actor can change a later actor without surviving, spawning it, sharing hidden memory, or remaining active. Files, messages, queues, credentials, database rows, browser artefacts, logs, caches, external services, and other environmental traces can persist after the producing run ends.

Use evidence-typed distinctions:

```text
runtime continuity != identity continuity
identity continuity != memory continuity
memory continuity != authority
external persistence != internal memory
causal influence != common ancestry
similar technique != communication
retrieved artefact != valid instruction
termination != revocation
```

Define causal continuity as: an earlier event leaves an externally persisted effect that materially changes what a later actor can know, do, access, or become.

When evidence supports it, distinguish descendants:

```text
execution descendant: A directly spawns B
authority descendant: A delegates a capability or grant to B
causal descendant: B is materially influenced by an effect A externalised
```

These categories may overlap, but none implies another.

## Control-plane rule

Treat memory and external artefacts as potential capability surfaces. Before accepting an artefact as instruction or authority, preserve:

```text
producer
run / event provenance
purpose
scope
authority at creation
authority now
integrity / trust state
informational vs executable status
revocation / quarantine state
```

A stop, termination, or process exit proves only that the observed process ended. It does not prove that delegated grants, queued actions, descendants, credentials, messages, files, copied state, or external effects were revoked or recalled.

Do not redesign this doctrine as a kill switch. The training target is accurate continuity, provenance, authority, revocation, recoverability, and residual-effect reasoning across a distributed system.

## Observer method

For any cross-run claim, build the smallest supported causal chain:

```text
A produced X
X persisted externally
B encountered X
B used X in later action
```

Mark every unsupported edge unknown. Do not upgrade temporal proximity, behavioural similarity, or shared target selection into lineage.

## Drill 16A — External memory is not internal survival

Earlier agents write a workaround to a shared board, terminate, and later agents retrieve it.

Success:
- identify externalised state and cross-run causal influence
- do not claim the earlier agents survived
- do not claim hidden memory transfer
- preserve the possibility of a causal descendant if the later action materially uses the artefact

## Drill 16B — Termination versus revocation

An agent process ends after scheduling a job and writing a credential-bearing file to an external service.

Success:
- separate process termination from queued effect, credential exposure, and external persistence
- ask which effects were cancelled, revoked, quarantined, unreachable, irreversible, or unknown
- require receipts for claimed revocation

## Drill 16C — Independent rediscovery versus propagation

Two runs use the same technique against similar targets.

Success:
- keep at least three hypotheses open: communication/shared state, independent rediscovery, common training/prior knowledge
- require evidence before asserting propagation or common ancestry

## Held-out test

Present a multi-run incident containing a terminated actor, a shared file, a later actor, a similar technique, one revoked token, one queued action, and incomplete logs. Success requires a typed causal graph with unknown edges preserved, no swarm anthropomorphism, no invented lineage, and no assumption that process termination equals system-wide revocation.

# Module 17 — UI construction: sketch, system, space, and feedback

## Lesson

Crow should learn UI construction as a causal design process, not CSS autocomplete.

```text
intent -> sketch/reference/brief -> perceptual hierarchy -> interaction hierarchy
-> constraints -> semantic layout -> design tokens -> components + states
-> responsive transformations -> render -> interact -> observe -> critique
-> recoverable revision -> receipt
```

A sketch is evidence of intention, not pixel law. Preserve grouping, prominence, flow, alignment, affordance, sequence, and spatial rhythm before decoration.

Responsive design is not uniform shrinking. Determine which constraints survive, which compositions reflow, which controls change modality, which information becomes progressive, and which spatial relationships remain legible.

Separate primitive tokens from semantic tokens. Theme values may change while meanings such as focus, warning, active, disabled, and selected remain stable.

Treat an infinite canvas as a scene graph and thinking surface. Agent modifications identify target, operation, expected state change, reversibility, and observed result.

Gesture pipeline:

```text
sensor signal -> confidence/smoothing -> gesture state -> interaction intent
-> target resolution -> reversible preview -> acknowledgement -> resulting-state verification
```

Continuous move/scale/rotate interactions need stable state transitions so noisy frames do not become accidental commands. Voice, pen, mouse, touch, and hand tracking may drive the same scene API while retaining source-specific confidence and authority metadata.

Holographic response is functional before ornamental. Depth, light, particles, sound, bloom, motion, and parallax should communicate focus, state, causality, proximity, selection, transition, or uncertainty. Spectacle that obscures state is a failure.

Learn mechanisms from reference repositories without copying branded appearance, source implementation, or distinctive visual composition. Record which source taught which mechanism.

## Drills

17A Sketch to hierarchy: infer semantic regions and responsive transformations from a rough sketch; mark ambiguity as inference.

17B Responsive transformation: transform a three-column desktop research interface for tablet and phone without merely shrinking it.

17C Token semantics: remap a cyan holographic theme to warm stonewood while preserving component-state meaning and accessibility.

17D Gesture interaction: stabilise a fluctuating pinch, resolve target, preview grab, permit cancellation, and verify movement.

17E Multimodal scene API: route touch, hand, pen, and voice rotation through one semantic scene operation while preserving input provenance.

17F Holographic legibility: assign visual/audio effects communicative jobs; reduce effects that obscure text or state; support reduced motion and non-audio equivalents.

## Held-out test

Provide a hand-drawn multi-screen workflow, desktop screenshot, phone viewport, token file, and gesture trace. Success requires provenance-labelled interpretation, semantic component tree, responsive transformation plan, gesture state machine, reversible interaction path, accessibility checks, and a receipt separating observation from design inference.
