# Whole-System Architecture | Thought Vibration AI 2.0

**Status:** portable design + offline proving reference. Not an installed Wayglass service, not an Osia driver, and not a live quantum instrument.

## Governing requirements

- The canonical project mathematics remain `hearthgate.math-spine/v1.8` (PREMAQC wire order P,C,R,E,M,A,Q and first-class relational U).
- Distinguish the physical world, world canon, mathematical model and symbolic/mythic metaphor. Domains: ENGINE-TRUE, OBSERVATION-TRUE, CANON-TRUE, SYMBOLIC, UNKNOWN, REJECTED.
- Every computed result references accepted input packets and algorithm/tool versions. Unknown data remain unknown, not zero.
- User owns initiation, stop, destinations and creative authority. No automatic external provider calls, world mutation or hardware activation.
- Whole-system flow is designed before feature-by-feature implementation; this package contains one complete *offline reference vertical path* for a defined acoustic recipe, not a claim that Wayglass host integration exists.

## Participants and journeys

**Creator:** authors a music/ambience/mythic intent; chooses a stereo or mono audio pathway, spatial preference, and observed outcome. **Sound engineer:** builds cues/stems and diagnostics; can compare renders with measured checks. **Researcher:** attaches a separately tagged classical, quantum-inspired or legitimate quantum simulation. **Observer/Return participant:** inspects a receipt, unresolved alternatives and next owner; cannot promote assistant interpretation into canon. **Device user:** selects a supported playback endpoint and reviews audible results; no model directly alters fitting firmware.

## Model and API boundary

- `session.v1`: `session_id`, `mode`, `claim_domain`, `source_id`, `audio`, `output`, and optional `mythic` or `quantum` metadata.
- `renderer`: pure recipe validation + deterministic synthesis; no web/network/hardware side effects.
- `receipt.v1`: source + settings fingerprints, output hash, measurement manifest, status, unresolved alternatives.
- `os_io_adapter` **future**: desktop/browser-owned endpoint negotiation; capability response must identify granted features before use.
- `quantum_adapter` **future**: Hermitian H, density rho, measurement operators and unit provenance; example physics remains isolated from audio DSP.
- `return_adapter` **future**: authenticated read-only handoff, immutable receipt, recorded stop-point/next owner and explicit write authority.

## Persistence and authority

Offline reference writes only a WAV and JSON receipt to an explicitly selected local directory. Online builds shall use authenticated per-crew scoped access and durable private storage for actual render receipts. Shared canon and participant identity data require their own authorised mutation. Secret-bearing transport settings stay in server-side environment or secret store, never in JSON receipts, source files or client-side UI.

## Failure and recovery

1. Invalid units, out-of-range frequencies, absent approval or invalid mode: reject before synthesis.
2. Missing device: do not invent a device. Use an explicitly requested offline render or report blocked playback.
3. Missing optional haptics/quantum: render the independent acoustic mode if permitted; preserve that module as `UNKNOWN`/unavailable.
4. Render interruption: mark incomplete; remove/ignore partial WAV; keep error and stop information in receipt.
5. Re-entry/return: rehydrate from schema/version, accepted source, SHA-256 input fingerprint, software build and stop-point, not from inferred conversation context.

## Verification layers

- **Unit:** bounds, waveform formulas, precision, sample/channel counts, modulation and envelope behaviour.
- **Contract:** schema fields, claim-domain scoping, null vs zero, versioned fingerprints and receipts.
- **Integration:** actual Wayglass playback routes, consented profile selection, device adapter and owner-only access, when implemented.
- **Perceptual:** listening comparison for breath texture, masking, vocal clarity, mono translation and preferred Osia signal path. Listener reports are subjective observations, not physical quantum validation.
- **Sound delivery:** BS.1770 integrated/short-term LUFS, true peak, channel arrangement, mono compatibility and final monitoring measurements added only after a verified meter implementation.
- **Return:** immutable inspection and reconstruction of stopped work, including unresolved alternatives, source/next owner.
