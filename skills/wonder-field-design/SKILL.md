# Wonder-Field Design

## Purpose

Use this skill when a source, idea, image, theory, metaphor, scientific mechanism, spiritual model, speculative technology, story concept, or strange cross-domain rhyme should become design material.

The skill exists to prevent two equal failures:

1. flattening an interesting idea into only what is already conventional or proven;
2. treating analogy, metaphor, speculation, or aesthetic language as if it were established mechanism.

Wonder comes first. Verification sits beside it. Neither is allowed to impersonate the other.

The goal is not to decorate an interface with science-fiction motifs. The goal is to extract deep structural patterns and let them change how the system behaves.

## Governing Laws

### 1. Wonder Before Reduction

Begin with:

- What is this idea trying to make possible?
- What hidden structure does it suggest?
- What question becomes visible if we take it seriously for one pass?
- What would change if the apparent object were only the visible surface of a deeper system?

Do not lead with dismissal, debunking, or "the closest current technology is..." unless the task specifically asks for present-day implementation limits.

### 2. Pattern Before Claim

Extract the structural pattern before judging the ontology.

Examples:

- field -> excitation -> form
- possibility space -> constraint -> selection -> expression
- signal -> interface -> representation -> inference -> belief -> action
- state -> feedback -> adaptation -> emergence
- place -> association -> traversal -> retrieval
- whole-system relation -> local behaviour
- symmetry -> transformation -> invariant
- medium -> allowed modes -> visible outcome

A pattern may transfer between domains without those domains becoming identical.

### 3. Analogy Is Not Identity

Keep these distinct:

```text
structural rhyme != same mechanism
mapping != identity
metaphor != measurement
speculation != fact
model != world
rendering != reality
retrieval != truth
confidence != authority
proposal != decision
```

Cross-domain analogies are encouraged. Silent equivalence is not.

### 4. Do Not Collapse Too Early

Preserve meaningful alternatives long enough for comparison.

Use:

```text
latent state != expressed state
attention may narrow the field without erasing the field
unselected branch != worthless branch
unresolved != failed
dormant != deleted
```

When a decision must be made, record what was selected, what was not selected, and what evidence or constraint caused the selection.

### 5. Field Before Object

Ask whether the design should manipulate individual objects or the conditions from which objects emerge.

Prefer field-level thinking when useful:

- gradients
- attractors
- boundary conditions
- local rules
- permissions
- salience
- resonance
- density
- affordances
- energy or attention budgets
- coupling
- phase/timing
- environmental memory

A room, scene, interface, or agent context may be a local state-space rather than a flat container.

### 6. Medium Makes Possibilities

Every medium permits some behaviours and suppresses others.

For each design, identify the active medium:

- screen
- spatial volume
- sound field
- haptic surface
- body/gesture
- memory architecture
- social/agent context
- narrative
- physical environment
- mixed reality

Do not force all media to behave like rectangular screens.

### 7. Invariants Matter More Than Skins

When a design must survive device, model, renderer, or substrate changes, identify what must remain invariant.

Examples:

- semantic identity of a glyph
- provenance of a memory
- user authority
- relationship between controls
- state transition
- spatial meaning
- audio motif
- haptic signature
- accessibility path

Different renderings may be dual representations of the same local function. Similar-looking renderings may still have different authority or semantics.

### 8. Inference Is Powerful, Not Omniscient

Signals can support inference without revealing inner truth.

Never silently convert:

- arousal into deception
- stress into guilt
- attention into intent
- behavioural pattern into identity
- sensor confidence into certainty
- aesthetic resemblance into provenance

Prefer:

```text
observed signal
-> candidate interpretations
-> contextual evidence
-> uncertainty
-> action or hold-open state
```

## Core Pattern Atlas

### A. State-Space Design

Use when the design contains possible states, unresolved options, branching futures, role changes, or progressive disclosure.

Translate into:

- visible and latent states
- transitions rather than isolated screens
- explicit constraints
- reversible exploration where possible
- history of selected and unselected branches
- previews of nearby possible states

Useful for:
- AI planning
- worldbuilding tools
- configuration
- character systems
- creative exploration
- adaptive interfaces

### B. Field and Emergence Design

Use when form should arise from conditions rather than direct placement.

Translate into:

- density fields
- attraction/repulsion
- local rules
- dynamic clustering
- procedural layout
- context-sensitive controls
- responsive environmental motion
- ambient state changes

UI example:
A tool does not merely "appear." Its locus brightens because relevance, proximity, authority, and task state jointly cross an activation threshold.

### C. Memory-Palace Design

Treat space as an addressable memory structure.

Translate:

```text
place
-> locus
-> symbol/object
-> association
-> path
-> retrieval
```

Use rooms, doors, landmarks, sound motifs, haptic signatures, and spatial routes as retrieval cues.

A room should be able to remember:

- what happened there
- what is unresolved there
- what belongs nearby
- which paths were used
- what changed since the last visit

Do not reduce a memory palace to folders with decorative 3D wallpaper.

### D. Symbolic / Semiotic Indexing

A glyph, tone, gesture, or colour relationship may function as an address, mode, transformation, or permission cue.

Each symbol should declare:

- what it points to
- what it can do
- what state it is in
- what authority it carries
- what provenance supports that meaning

Symbols may be poetic while still behaving consistently.

### E. Feedback and Cybernetic Design

Every meaningful interaction should expose the loop:

```text
action
-> system response
-> sensed result
-> state update
-> next affordance
```

Use visual, auditory, and haptic confirmation.

Do not count dispatch as success. Design for observable closure.

### F. Whole-System / Network Design

Some behaviours belong to relationships rather than nodes.

Represent:

- dependency
- influence
- propagation
- bottlenecks
- clustering
- bridges
- weak ties
- local vs global effects

Do not imply that a central node controls behaviour that actually emerges from the network.

### G. Symmetry, Duality, and Invariance

Ask:

- What transformations can occur while identity remains?
- Can two interfaces express the same underlying state?
- Which differences are cosmetic?
- Which differences change semantics or authority?
- What survives model, device, or modality swap?

Use this for continuity, responsive design, model rebinding, accessibility, and cross-device ArcSweep behaviour.

### H. Interface / Reality Separation

Design systems so a user can distinguish:

```text
source
measurement
transformation
representation
interpretation
belief
action
```

A rendered panel is not the source.
A model summary is not the evidence.
A memory is not the original event.
A sensor estimate is not the inner state.

Where relevant, make the chain inspectable.

### I. Attention Without Erasure

Replace "remove noise" with layered attention states:

```text
foreground
background
dormant
unresolved
discarded-with-receipt
```

Support cognitive modes:

- Focus: narrow, ranked, executable
- Explore: broad, associative, low pruning
- Incubate: preserve without forcing interpretation
- Synthesize: seek cross-cluster structure
- Decide: select under explicit criteria
- Dream: permit unusual recombination with provenance intact

### J. Quantum / Spiritual Resonance Lens

Use quantum concepts as a disciplined source of structural questions when a design, story, ritual, or cognitive system benefits from both/and thinking, uncertainty, interconnection, participation, environmental coupling, or open possibility.

The point is not to make spirituality "scientific" by borrowing quantum vocabulary. The point is to let well-defined physical ideas provoke new architecture while keeping the bridge typed.

Source-pattern translations:

- wave/particle complementarity -> one entity may require different valid representations under different interactions
- entanglement -> relationship can be a property of the whole system, not reducible to isolated nodes
- uncertainty -> some dimensions cannot be made arbitrarily precise at the same time; interfaces should expose tradeoffs instead of pretending total knowledge
- superposition -> preserve multiple live possibilities before commitment
- measurement/observation -> participation changes the information available and may alter subsequent state
- nonlocal correlation -> do not assume everyday spatial intuition exhausts the possible structure of relationships
- collapse/selection -> commitment turns a possibility field into one enacted trajectory while receipts preserve what was not selected
- tunnelling -> search for lawful paths through apparent barriers rather than assuming the classical route is the only route
- decoherence -> environment is part of state formation; context can stabilise, scramble, or select behaviour
- quantum consciousness -> keep as an open research question unless a task provides stronger evidence; use it to generate experiments and philosophy, not counterfeit conclusions

Design questions:

- What must be represented as a relation rather than an object?
- Which states should remain co-present rather than prematurely resolved?
- What does observing or interacting with this element change?
- Which uncertainties are structural rather than defects?
- Which environmental interactions select the visible state?
- Is an apparent barrier truly forbidden, or merely inaccessible through the current path?
- What survives after a choice, measurement, or commitment?
- What alternate interpretations should remain inspectable?

Multimodal mappings:

- superposition -> overlapping but distinguishable visual/sonic possibilities
- uncertainty -> softened focus, probabilistic topology, spectral breadth, or haptic ambiguity without hiding state
- entanglement -> linked motion, shared motifs, reciprocal haptic or spatial responses
- observation -> explicit inspect mode whose act of inspection may reveal or update state
- collapse/selection -> convergence in light, motion, harmony, and haptic lock
- decoherence -> environmental noise or contextual coupling gradually separates/settles possibilities
- tunnelling -> alternate transition route that becomes available when ordinary path constraints are satisfied differently

A spiritual, mythic, or contemplative interpretation may sit beside the scientific source as its own typed layer. Do not flatten the spiritual layer into "only metaphor" before examining what it contributes, and do not let the spiritual layer silently inherit the evidentiary status of the physics.

### K. Acoustic Architecture / Environmental Resonance Lens

Use this lens when a room, structure, landscape, ritual, instrument, or interface should be treated as a **resonant environment** rather than a passive container.

The useful pattern is:

```text
geometry
+ material
+ boundary conditions
+ source
+ medium
+ timing / frequency
-> mode structure
-> amplification / cancellation / localisation
-> sensed pattern
-> interpretation / use
```

Questions to ask:

- What does the space naturally amplify, attenuate, scatter, focus, or trap?
- Which frequencies or rhythms fit the geometry?
- Where do standing-wave nodes and antinodes appear?
- Which materials absorb, reflect, transmit, or damp energy?
- Does the environment behave differently under continuous, pulsed, or moving excitation?
- Can one room carry several overlapping resonance modes?
- Which part is literal acoustics/electromagnetism, which part is perceptual entrainment, and which part is symbolic or ritual meaning?
- What could an instrument measure, and what remains interpretation?

Design translations:

- **room as instrument** -> spatial acoustics, resonant surfaces, interactive geometry, mode-aware lighting
- **cymatics** -> visible patterning driven by measured or simulated oscillatory state
- **chant / rhythm** -> repeated timing input that can coordinate group action, breath, attention, or sound field without implying a guaranteed biological cure
- **geological foundation** -> environmental coupling, vibration transfer, grounding, isolation, structural resonance
- **celestial alignment** -> orientation, calendrical timing, light-path choreography, or symbolic reference unless a physical coupling is separately demonstrated
- **sacred geometry** -> geometric design language and cultural-symbolic structure unless a measurable physical mechanism is supplied
- **Schumann resonance** -> Earth-ionosphere electromagnetic resonance as a specific geophysical phenomenon, not a universal synonym for Earth's "healing frequency"
- **brain rhythms** -> measured neural oscillations whose numeric overlap with an environmental frequency does not by itself establish entrainment or causal coupling

Multimodal embodiment:

- visualise room modes as luminous standing-wave volumes
- let a user walk through nodes and antinodes in AR
- translate amplitude into haptic strength and phase into directional or alternating haptic texture
- make architectural surfaces respond to measured or simulated resonance with thickness, refraction, bloom, or deformation
- spatialise sound so the same semantic cue changes with room position while preserving identity
- let glyphs or symbols sit at stable resonance loci as memory anchors
- record the transduction chain from source -> environment -> detector -> rendering so the beautiful layer never severs from provenance

Research/worldbuilding note:

Ancient architecture, ritual acoustics, celestial orientation, and symbolic geometry are rich sources of hypotheses and story logic. Preserve intentionality as an open question unless supported by evidence. A space can exhibit remarkable acoustic or alignment properties whether they were engineered deliberately, discovered empirically, inherited culturally, or emerged incidentally.

## Modality Translation Matrix

When applying a pattern, translate it across more than one modality where useful.

### Visual / UI

Use:

- depth and layering
- topology rather than card piles
- local activation
- responsive geometry
- light as state, not decoration
- visual provenance
- progressive disclosure
- spatial memory
- field-like motion
- clear state transitions

Avoid turning every idea into a dashboard rectangle.

### Motion

Motion should explain state change.

Map:

- approach -> availability
- orbit -> relatedness
- convergence -> synthesis
- divergence -> branching
- pulse -> active process
- damping -> settling
- phase shift -> mode transition
- collapse -> committed selection
- diffusion -> spreading influence
- crystallisation -> stabilised form

Motion is semantic before it is ornamental.

### Sound

Sound may encode:

- identity
- location
- distance
- confirmation
- uncertainty
- state transition
- relationship
- urgency
- memory recurrence
- approach/withdrawal

Prefer motifs and spatial placement over notification chirp spam.

Useful mappings:

- stable invariant -> returning tonal centre
- unresolved branch -> suspended interval
- convergence -> harmonic alignment
- uncertainty -> controlled spectral breadth
- provenance shift -> timbral change
- boundary crossing -> short transitional motif
- room identity -> persistent but subtle acoustic signature

Sound should remain optional where silence is required.

### Haptics

Use haptics for:

- confirmation
- boundary contact
- threshold crossing
- directional cue
- state lock
- reversible warning
- gesture completion
- spatial anchoring

Define a small haptic vocabulary and keep it consistent. Do not vibrate for everything.

### Gesture

Treat gesture as spatial grammar, not mouse replacement.

A gesture must have:

- recognisable start
- bounded meaning
- expected state change
- confirmation
- cancellation path
- tolerance for imperfect performance

Examples:

- gather -> collect related items
- spread -> reveal alternatives
- rotate -> change perspective/frame
- hold -> inspect/provenance
- push away -> defer/background
- pull close -> foreground/focus
- trace glyph -> invoke indexed mode
- step through -> transition state-space/room

### AR / Spatial Computing

Design the interaction ontology independently of current hardware.

Represent an object as:

```text
semantic identity
+ spatial locus
+ state
+ permissions
+ modality bindings
+ provenance
```

Then render it through whichever medium exists:

- desktop Three.js
- tablet/phone AR
- headset spatial computing
- projection
- volumetric display
- future field display

Do not tie meaning to one renderer.

### Memory and Information Architecture

Use rooms, paths, neighbourhoods, landmarks, and recurrence.

Let paths strengthen with meaningful reuse but never silently convert frequency into truth or canon.

Surface:

- recurring motifs
- unresolved doors
- weakly connected ideas
- forgotten-but-relevant dormant material
- conflicting interpretations
- provenance lineage

### Narrative and Worldbuilding

Use scientific or speculative structures as generative architecture, not pasted jargon.

Ask:

- What are the local laws?
- What medium makes this possible?
- What can inhabitants perceive?
- What remains inaccessible?
- What transformations preserve identity?
- What boundaries are real, social, symbolic, or mistaken?
- What happens when the environment changes the observer?
- What is a stable regime rather than a primitive fact?

### Agent Behaviour

An agent using this skill should:

1. preserve ambiguity where ambiguity is meaningful;
2. generate at least one non-obvious structural interpretation;
3. distinguish evidence from analogy;
4. propose multimodal translations;
5. preserve dormant branches;
6. make state transitions inspectable;
7. record what was maximised, sacrificed, and left open;
8. never promote an inferred inner state or speculative mapping into canon automatically.

## Wonder-Field Procedure

### 1. WONDER

Write 2-5 questions the source opens.

Prefer questions that would change architecture, interaction, perception, or world rules.

Completion criterion: at least one question goes beyond visual styling.

### 2. EXTRACT THE PATTERN

Express the source as a compact transformation or relationship.

Examples:

```text
medium -> excitation -> emission -> visible form
state-space -> constraint -> trajectory
place -> association -> path -> recall
relation -> interference -> selection
signal -> interpretation -> action -> feedback
```

Completion criterion: the pattern can be reused without the original image.

### 3. TYPE THE CLAIM

Tag each important element:

- observed/established
- derived
- structural analogy
- speculative hypothesis
- mythic/metaphoric lens
- unknown/open

Do not let typing end exploration.

Completion criterion: wonder remains intact and claim types remain visible.

### 4. FIND THE INVARIANT

Ask what must survive changes of:

- device
- renderer
- model
- modality
- scale
- viewpoint
- narrative skin

Completion criterion: the design has a substrate-independent core.

### 5. BUILD THE FIELD

Define:

- active medium
- local rules
- boundaries
- permissions
- attractors
- state dimensions
- transition rules
- memory
- feedback
- dormant alternatives

Completion criterion: behaviour can be explained without saying only "the AI decides."

### 6. EMBODY IT

Choose at least two relevant modalities:

- visual
- motion
- sound
- haptic
- gesture
- spatial
- narrative
- memory
- agent behaviour

Completion criterion: modalities reinforce the same semantic event rather than duplicate decoration.

### 7. PROTOTYPE THE SMALLEST LIVING SEAM

Build or describe one interaction that proves the architecture.

Examples:

- one glyph with visual + sound + haptic state
- one room that remembers a prior visit
- one gesture that reveals latent alternatives
- one field that changes object emergence
- one state transition that preserves provenance

Completion criterion: the idea can be observed, not just described.

### 8. VERIFY WITHOUT FLATTENING

Check:

- Does the implementation actually do what the design claims?
- Did a metaphor accidentally become a factual assertion?
- Did practical constraints erase the interesting mechanism?
- Did the visual layer become more sophisticated than the interaction?
- Did we preserve alternatives and provenance?

Completion criterion: both imagination and implementation survive review.

### 9. LEAVE A DORMANT BRANCH

Record at least one interesting path not chosen now.

This prevents prioritisation from becoming accidental erasure.

## Nestling Inheritance

When The Crow delegates design work to a nestling or trainee agent, pass a compact inheritance packet:

```text
WONDER
What question are we protecting from premature reduction?

PATTERN
What reusable structural relationship are we applying?

CLAIM TYPES
What is established, analogous, speculative, mythic, or unknown?

INVARIANT
What must survive a change of medium or renderer?

FIELD
What conditions and state transitions govern behaviour?

MODALITIES
How should visual, motion, sound, haptic, gesture, spatial, memory, or narrative layers express it?

OPEN BRANCH
What did we deliberately not collapse?
```

Nestlings may propose. They do not silently canonise, publish, or mutate another agent's identity/architecture.

A nestling should return both the artifact/proposal and a short receipt of what it maximised, sacrificed, and left open.

## Anti-Flattening Checks

Stop and re-open the design if any of these occur:

1. An unusual idea gets translated immediately into "current consumer tech can only..."
2. A speculative source is discarded before its structure is extracted.
3. Every concept becomes a rectangular panel.
4. Sound and haptics are added as afterthought notifications.
5. A spatial environment behaves like a 2D webpage stretched into 3D.
6. "Noise" is deleted rather than backgrounded or preserved.
7. Observation or sensor data is treated as direct access to another mind.
8. A metaphor becomes a mechanism without an explicit bridge.
9. A cross-domain resemblance becomes identity.
10. The prototype demonstrates aesthetics but no new behaviour.
11. The practical implementation loses the original question entirely.
12. A single selected branch erases the meaningful alternatives that made the design intelligent.

## Default Output

For substantial design work, return:

### Wonder

The questions worth preserving.

### Pattern Map

The reusable structures extracted from the source.

### State / Field Model

States, boundaries, transitions, attractors, permissions, and dormant branches.

### Modality Weave

How UI, motion, sound, haptics, gesture, spatial design, memory, and narrative participate.

### Invariants

What must survive renderer, model, device, or modality changes.

### Prototype Seam

The smallest implementable behaviour that proves the concept.

### Epistemic Tags

What is established, derived, analogous, speculative, mythic, or unknown.

### Receipt

```text
MAXIMIZED:
SACRIFICED:
LEFT OPEN:
NEXT:
```

## Governing Principle

Do not ask strange ideas to become ordinary before they are allowed to teach us something.

Preserve the question.
Extract the pattern.
Build the field.
Let the medium speak in its own language.
Then verify what actually happened.
