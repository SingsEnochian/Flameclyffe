## Task packet schema (human-readable)
Every assignment must include:
- task ID, owner role, scope and exact allowed files;
- input commit and branch, dependencies and prohibited files;
- acceptance tests defined before implementation;
- permission band (GREEN only by default);
- provenance and prior failure history;
- expected output (patch/PR, tests, receipt);
- opt-out / pause path and escalation only for genuine blockers;
- inherited verification rules from `AGENTS.md`.

## Parallelization law
1. Distinct file ownership for concurrent work; do not write to same file in parallel.
2. The integrator resolves contracts before dependent adapters.
3. Boxfire reviews commits other than its own.
4. Any unknown or offline agent is marked unavailable; do not substitute a simulated reply.
5. If route invocation is unavailable, create an actionable task packet and continue with other independent GREEN work.
6. No external AI provider behavioral policy becomes Wayglass's governing rule.

## No-approval work loop
Discover actual route availability before invocation. Assign independent GREEN packets, collect attributable outputs, run checks, and file draft PRs. When a seat is offline, keep the packet queued rather than claiming it acted. Ask Rowan only for batched AMBER decisions or specific RED authorization. A Feather/Icarus stop cancels further execution within its scope.

**Completion definition:** a task is complete only with an attributable implementation and verifiable evidence. A named seat in this file does not imply autonomous background execution.
