## Complete system responsibility

Authenticated MCP ingress receives a current resource-bound owner/participant grant; it snapshots request meaning before asynchronous checks and writes an immutable private host receipt. Queue notification contains only custody metadata. Recovery discovers queued keys from private storage after restart, reloads and validates each receipt, checks current resource-bound grants and Feather, and submits to the receiving host. The receiving host owns atomic deduplication by `receipt_id`, Feather at its side-effect boundary and attributable review. Neither ingress nor adapter fabricates a reply or decision.

State owner: private receipt store. Authority owner: injected trusted grant authorizer and host stop callback. Storage must be an explicitly provisioned private directory outside checkout/web roots. The host owns parent-directory creation and durability. This module does not create directories recursively and then imply that their ancestry is durable.

## Defects corrected from prior candidate

1. Resource audience was not persisted or included in the idempotency key. Schema `wayglass.presentation-receipt/v1` binds resource, subject, grant and presentation, and delivery rejects audience changes. Legacy unbound receipts fail delivery; they are retained as evidence rather than silently migrated.
2. Caller payload and principal fields could change across the authorization await. Ingress now serializes and validates a captured payload and captures identity/grant before its first await.
3. A directory fsync failure after atomic publication could later be reported as a successful duplicate. Every read and duplicate/recovery path now requires directory fsync, including retry. Unsupported/failing filesystems fail closed and preserve complete published evidence for explicit recovery on a supported host.
4. Cold queue recovery lacked discovery. Resource-filtered, bounded metadata pages discover keys without returning private payloads. Malformed evidence fails the scan; it is never silently skipped.
5. Delivery could claim submission on any resolved bridge callback. It now requires acceptance of the exact receipt, rechecks Feather after authorization, and retains queued evidence on unknown/failed acceptance.
6. Host directories and receipt files enforce private modes on POSIX; receipt symlinks are rejected. Hard-link and directory-fsync support remain required. Windows directory-fsync compatibility is unverified and must not be represented as supported.

## Integration and remaining blockers

Supply explicit `resource` to every presentation ingress call. Delivery requires `{store, resource, authorize, isStopped, deliver}`. `isStopped()` must explicitly return `false` to proceed. `deliver()` must return `{accepted:true, receipt_id}` for that exact receipt. Both source forms (`phases`/`name` and `eightfold`/`phase`) retain the canonical eight phase names.

The store is immutable submission evidence; an accepted retry may be attempted again after return. There is no distributed exactly-once delivery claim. A receiving production host must atomically deduplicate and enforce Feather immediately before its side effect. Store discovery is trusted host functionality and must never be exposed as an unauthenticated public API.
