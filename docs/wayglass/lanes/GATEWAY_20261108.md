## Ownership and complete-system interface

This lane owns transport-neutral JSON-RPC core, Node HTTP handler/server factory, resource metadata and offline authorization-server metadata validation. Authenticated requests pass trusted owner/consent attribution to injected native services. OAuth verification, native route permission filtering, durable receipts, Feather and hosting are independently owned integration dependencies.

`createWayglassMcpServer({ resourceUrl, authorizationServerUrl, verifyBearer, listRoutes, present })` is the composition interface.

- `verifyBearer(token, {resource, requiredScope})` must validate credentials and current owner grant; scope remains `wayglass:constellation` at this boundary.
- `listRoutes({principalId, scopes, resource, consentRef})` must enforce route-specific permissions, including separate `wayglass:bluebird` consent. Bearer credentials never cross that interface.
- `present({principal, resource, payload})` is optional and advertised only when a trusted host binds it. Presentation ingress owns its additional current-grant check and receipt semantics.
- Unbound `listRoutes` now fails closed. The older default to the unfiltered global route catalogue has been removed.
- No runtime persistence is owned by the protocol factory. `/healthz` describes only process/factory facts; `/readyz` remains 503 without verified cloud composition. Hosting lane owns its independently verified readiness wrapper.
- Protocol supports JSON POST request/response, initialized-notification 202, optional ping and GET 405 (SSE unsupported). No stateful sessions, SSE resume, client cancellation dispatch or full MCP conformance certification is asserted.
