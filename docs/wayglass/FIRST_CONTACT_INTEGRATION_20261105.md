## Complete arrival flow

1. A fresh default launch opens Living Watercolor without requiring the optional Bluebird connection. All existing rooms, authorization APIs and voyage/recovery APIs remain available; explicit room deep links remain explicit destinations.
2. Paint by pointer/Pencil/keyboard, select an expressive mode, add your contribution or voice-authoring notes, and deliberately invite a registered route. Local-first routing does not silently substitute OpenAI.
3. A returned contribution needs matching route, provider, model and a real provider/host observation reference. Retain incomplete raw responses without presenting them as attributed speech. Actual pending/responded/failed route events feed pigment.
4. Save/recover the exact conversation and session explicitly in the private browser origin. Recovered turns are supplied as history on the next chosen request; recovery itself does not perform inference or start sound.
5. Navigate into Acoustic Room or another existing room and back. Shared Feather state survives room changes; late requests cannot speak or paint after stop or teardown. Release is explicit and does not restart effects.

The kernel's canonical dispatch preflight checks declared world/Waygate/continuation contracts before provider execution. Existing route-specific permission/transfer checks, stored checkpoints and inheritance resolution remain in place. Kernel readiness is not substituted for host authorization. No new public ingress or tunnel is introduced.

## State ownership

- Host/kernel retains participant semantics, route execution and durable departure custody.
- Watercolor bridge owns bounded session activity/proposals; the fluid solver owns reusable bounded simulation buffers.
- Somatic sound owns the shared Feather latch and explicit release marker; visual/Journey/acoustic views project it.
- Watercolor continuity owns attributable local transcript records. Browser-local and host-fsync custody are distinct. Host save/recover requires explicit caller declarations and a returned durable storage receipt; these calls are not automatic.
- Participation adapter accepts a decision only from an exact invitation-bound structured output. It keeps nullable provider response IDs separate from host observation IDs. Route identity is never invented as participant identity; the visual UI does not announce an accept/deny before a genuine participant binding exists.
