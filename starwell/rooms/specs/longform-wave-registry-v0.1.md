# Longform Wave Registry v0.1

The Longform Wave Registry retrieves adjacent manuscript material by resonance, provenance, and privacy class. It is a registry for longform writing context, not a hidden memory slurry and not a telemetry collector.

## Purpose

When a room is active, the current writing state may ask the registry for prior prose that resonates with the present scene, node, or draft direction.

The registry returns display-safe retrievals:

- source title
- source id
- chunk id
- short excerpt or summary
- resonance score
- privacy class
- provenance metadata

## Boundary

The registry does not own the UI.

The registry does not call browser APIs.

The registry does not receive raw location, battery, or device signals.

The registry does not mutate model parameters.

The registry does not publish retrieved prose. It only returns retrieval candidates to a review-gated surface.

## Core objects

### LongformCorpusRecord

Represents a manuscript, draft, chapter, scene, note, or canon document.

```json
{
  "record_id": "moonroot-chapter-01",
  "title": "Moonroot Chapter 1",
  "source_path": "local://manuscripts/moonroot/chapter-01.md",
  "project": "terra-aeterna",
  "privacy_class": "private_draft",
  "canonical_status": "draft",
  "created_at": null,
  "updated_at": null
}
```

### LongformChunk

A chunk is the retrieval unit. It should preserve enough provenance to return the writer to the original source.

```json
{
  "chunk_id": "moonroot-chapter-01:0007",
  "record_id": "moonroot-chapter-01",
  "text": "...",
  "summary": "Falka pauses at the moon window and hears the tide under the floor.",
  "position": {
    "start_char": 4120,
    "end_char": 4860
  },
  "tags": ["moonroot", "tidal", "quiet"],
  "privacy_class": "private_draft"
}
```

### WaveSignature

A compact representation of a chunk or query in real/imaginary resonance space. A signature can be generated by the resonance model, a lexical baseline, or a future embedding adapter.

```json
{
  "signature_id": "moonroot-chapter-01:0007:wave-v1",
  "chunk_id": "moonroot-chapter-01:0007",
  "model": "narrative-resonance-v0.1",
  "real": [],
  "imag": [],
  "hash": "..."
}
```

## Query packet

The room runtime may send a query packet to the registry after consent and storage rules are checked.

```json
{
  "room_id": "moonroot-writing-chamber",
  "action": "longform_resonance_query",
  "query_text": "",
  "query_signature": {
    "real": [],
    "imag": []
  },
  "filters": {
    "project": "terra-aeterna",
    "privacy_class": ["private_draft", "review_gated"],
    "canonical_status": ["draft", "canon_candidate"]
  },
  "limit": 5
}
```

Raw text should be omitted when the room has not enabled live text. Query signatures may still be generated locally from explicit room actions, save events, selected nodes, or manually submitted text.

## Result packet

```json
{
  "results": [
    {
      "record_id": "moonroot-chapter-01",
      "chunk_id": "moonroot-chapter-01:0007",
      "title": "Moonroot Chapter 1",
      "summary": "Falka pauses at the moon window and hears the tide under the floor.",
      "excerpt": "Short review-safe excerpt only.",
      "resonance_score": 0.82,
      "privacy_class": "private_draft",
      "source_ref": "local://manuscripts/moonroot/chapter-01.md#char=4120-4860"
    }
  ]
}
```

## Resonance scoring

Initial scoring may use complex-style interference:

```text
score = mean(query_real * chunk_real + query_imag * chunk_imag)
```

The score should be normalised before display. Later versions may combine:

- lexical overlap
- semantic embeddings
- wave interference
- project filters
- node context
- recency within a draft
- writer-pinned priorities

## UI mapping

The room renderer may consume registry metrics as display values:

- high resonance -> brighter archive pool
- multiple adjacent chunks -> more tendril branches
- low confidence -> dim, uncertain glow
- selected retrieval -> pulse from current node to archive node

The UI should state that retrieval is suggestive, not truth. It shows related prose; it does not decide canon.

## Safety and consent

No hidden corpus ingestion.

No automatic publishing.

No location or battery signals.

No raw typing rhythm unless explicitly enabled and reduced to coarse interaction rhythm.

No private draft display without visible privacy label.

No cross-project retrieval unless the user selects the project scope.

No retrieved prose should be inserted into a draft without explicit action.

## Replacement for raw prototype payload

Instead of sending browser telemetry directly into corpus retrieval, the service should receive an explicit query packet and compose only allowed context.

Unsafe pattern:

```python
retrieved_prose, resonance_score = corpus_registry.query_corpus_resonance(real, imag)
```

Safer pattern:

```python
result_packet = longform_registry.query(
    query_signature=query_signature,
    filters=filters,
    limit=5,
)
```

The room may use `result_packet.results[0].resonance_score` to animate the Archive Pool, but the registry remains a retrieval service with provenance and consent boundaries.
